# 新城市：从一句话到一本手册

2026-09-19 用户要的东西：「以后要去哪个城市跟你讲一声，你就能自动找了推荐？我自己选？」
——是。这份档案是那条流水线的正本。

**分工只有一条线**：**找、查、抓、排版＝机器的事；要不要去、合不合口味＝用户的事。**
凡是机器能判的（评分、营业时间、有没有牛肉、离住处多远、照片是不是菜单），
一律不要拿去问用户；凡是需要偏好的（想不想去、老板喜不喜欢），一律不要替他决定。

## 0. 先问清楚（一次问完，不要挤牙膏）

缺了这几项做出来的清单会白做，所以开工前一次问齐：

| 要问的 | 为什么 |
|---|---|
| 城市＋日期 | 决定季节、节庆档期、要不要查天气 |
| 几个人、有没有老人小孩 | 决定亲子场所与步行强度 |
| 住哪（酒店或区域） | 决定「离住处多远」这条筛选 |
| 忌口／偏好 | 槟城那趟是「不吃牛」；这条会直接筛掉整批餐厅 |
| 有没有已经定好的行程 | 别推荐跟已定行程冲突的 |

用户一次讲不全也没关系——**能查的自己查**（例如酒店地址、节庆档期），
只把真的只有他知道的（谁同行、忌口）问回去。

## 1. 派研究员找候选

委派写法见 `.claude/playbook/templates.md`；这里只讲这一类任务的特殊要求：

- **门槛写进 prompt**：餐厅／景点 ≥4.2；电玩城、保龄球、体感运动馆这类游艺设施 ≥3.8
  （门槛正本在 CLAUDE.md，别在委派里另立标准）
- **每个候选必须带回**：名称、中文名、类别、评分、评价数、**地图链接（cid 最好）**、
  推荐理由（一句话讲清楚「为什么是这家」）、营业时间、地址
- **景点和吃饭分开**：熟食中心、美食广场、小贩中心、夜市摊这类「去吃东西的地方」只能进餐厅
  候选，**不准当景点推荐**（2026-10-31 用户问「Maxwell 算景点？」，2026-11-04 又把老巴刹、
  中峇鲁市场、纽顿放进景点清单，用户：「怎么连 food court 也放下去 专业点」）。委派研究员找景点
  时把这句写进 prompt，交给用户前自己再扫一次。
- **理由不能是废话**：「很有名」不算，「米其林必比登、辣度可调、小孩能吃」才算
- **数量**：一个城市 30~50 个，宁可多给让用户删，不要少给让他觉得没得选
- **产出格式**：直接交 JSON，形状见 `tools/build-shortlist.py` 的档案说明

## 2. 抓照片（CI 通道，沙盒抓不到）

把所有候选的地图链接串成 `|` 分隔，跑 `fetch-photos.yml`（`want: 8`）。
抓图器会自动从 Google 的「Food & drink」分类取图、OCR 把菜单照排到最后
（2026-09-19 用户明确要求：**店＋食物，不要菜单**）。

结果会提交回触发分支的 `.photos/latest.txt`。

## 3. 自己先看一眼（这一步以前会跳过，不要再跳）

`photo-preview.yml` 把照片缩到 500px 提交回分支，Claude 直接 Read 就看得到。
**每家至少看第一张**：确认拍的是这家店、不是隔壁、不是菜单、不是停车场。
2026-08-22 就发生过把商场照片当餐厅照片交出去。

看完把明显不对题的从候选里剔掉或换一张，再进下一步。

## 4. 生成候选清单页给用户挑

```
python3 tools/build-shortlist.py 候选.json --photos .photos/latest.txt \
    -o <城市>-trip/shortlist.html
```

页面长什么样、低于门槛怎么标、缺资料怎么显示，见 `tools/build-shortlist.py`。
上线后给用户网址（`https://jarixhew-bit.github.io/skills-github-pages/<城市>-trip/shortlist.html`），
并明说怎么回：「要 1 3 7 12，备选 5 9，其余不要」。

## 5. 用户挑完 → 出手册

**版型一律用 `sg-jkt-trip/singapore.html` 那套**（2026-11-01 用户定：「以后做手册都用这种设计，
跟着国家出主题」）：礼宾风整体（深色封面＋细金线＋象牙白内容区、衬线标题、罗马数字编号）、
每日站点竖线时间轴（每天一种当地交通线路色，压低饱和，避开警示红）、方角细框地图按钮
（线描地标针＋「地图 MAP」，≥44px）、可点元素要一眼看得出、按下发亮（照抄那两本 CSS 末尾「可点元素」一段＋`tapGlow` 小段 JS）、顶部每天跳转＋自动跳到当天。**主题跟着国家换**：
主色、纹样（用 CSS 画，不用图片）、时间轴线色取当地元素——雅加达那本（`jakarta.html`）
是范例：蜡染深棕＋kawung/parang 纹＋Transjakarta 线路色。去 AI 味：不用 emoji 当图标、
不用胶囊标签与大圆角阴影卡、不用 ✅⚠。新主题先截图给用户看过再套。
结构与坑见 `.claude/notes/travel-pages.md`。六件不能忘：

1. **登记行程日期**：新手册要在 `tools/lib/trips.py` 加一行，否则体检与自动补图
   不知道它什么时候该停（自检会点名漏登记的）
2. **卡片必须带图与中英说明**（CLAUDE.md 媒体规则）
3. **航班卡的飞行时长要算时差**（`check-flight-times` 会挡，但自己写的时候就该对）
4. **每天的站点顺路排、不走回头路**（2026-11-04 用户：「将来的行程都要按照这种排法」）：
   酒店出发往一个方向走到底再回城，不东西来回穿；判别法与「最短≠最顺」见 travel-pages.md 第 1 条
5. **天数写「X天Y夜」**（2026-11-08 用户：「为什么不是3天2夜、4天3夜这种说法」）：中文「4天3夜」、英文「4 Days 3 Nights」，不写「3晚4天」
6. **全本写成读者看的角度**（2026-11-09 用户：「要写成读者看的角度，不要写我们的角度」）：不写「逐家查好的」「已核对」「we checked」这类交代工作的话，直接写结果（`check-trip-hours` 会拦）

上线走 `publish-pages`。

## 事后自动维护（不用再管）

手册上线后这些自己会跑，用户什么都不用做：
- 每周一图片体检；破图当天自动补、自动开 PR
- 天气条、空气质量条现抓现显示
- 行程结束后自动停跑（`tools/lib/trips.py`）

## 自检

`python3 tools/check-shortlist.py` —— 验清单页产生器：编号连续、评分与地图链接
不漏印、低于门槛要标红但不消失、没照片不塌页、空候选干净报错。
