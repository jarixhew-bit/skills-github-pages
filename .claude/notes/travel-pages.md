# 旅游类页面结构笔记（给 AI 改页面用，不给游客看）

读者：要修改这六个页面的模型。行号会漂移，**以 id/class 锚点为准**。
改完必跑 `python3 tools/check-html.py 文件名.html`（标签平衡 + siteLangUser key 检查）。
背景规则：`skills/bilingual-pages.md`、`skills/media-files.md`、CLAUDE.md 双语/媒体规则。

## 通用坑（改任何一本手册都适用，2026-09-19 新加坡那轮踩出来的）

1. **挪动行程里的地点之前，先把那天其余站点在地图上的方向过一遍。**
   只判断「这一站塞得进那天吗」会造出折返路线：把新加坡观音庙（市区）挪进 D4，
   而那天前后都在义顺（北边），实际跑法变成「北 → 市区 → 回北」，白跑约 40 公里。
   是用户问「你这样排下去那个路线呢？」才发现的，不是自己查出来的。
   判别法：读每张卡自己写的地址与车程数字，别凭印象；同向的串成一条线，别来回穿城。
2. **跨天的说明要在两天各写一遍。** 「D2 这站来不及可以改到 D4」只写在 D2 卡上，
   当天翻到 D4 的人看不到。原处写进那张卡的 `.desc`，另一天在 `.wxbox` 之后、第一张
   `.stop` 之前补一个 `.note amber`，两边都要有。
3. **顶部 `.daystrip` 的 chip 顺序必须跟区块在页面上的先后一致。** `navSetup()` 判断
   「现在停在哪一段」是 `targets.forEach(t => { if (t.offsetTop <= pos) current = t; })`，
   取的是**链接数组里最后一个**已经滚过的区块——所以 chip 排错位的那一个永远轮不到高亮。
   新加坡手册的「🍷 备用」chip 本来排在 D1 前面，可它指的 `#boss` 区块在全页最后，
   结果滑到最底下亮的是 D5，那颗 chip 从上线起就没亮过（2026-09-21 用户问
   「你一直都没发现那个备用按钮放在错的地方吗」才发现）。加 chip 时对着区块顺序排一遍。
4. **要退回前几版就整档还原，别手工逐句改回去。** 做法：先
   `git log --oneline <基准commit>..HEAD -- <手册路径>` 确认这中间没有别的改动碰过这个文件，
   再 `git checkout <基准commit> -- <手册路径>`，最后 `git diff <基准commit> -- <手册路径>`
   确认输出为空。手工回退必留孤儿句子——改一个地点动到的远不止那张卡，还有天名（`.dn`/`.dt`）、
   那几天的雨天/烟霾备案、以及别的卡片里对这站的交叉引用（「离观音庙车程 3 分钟」这类）。
